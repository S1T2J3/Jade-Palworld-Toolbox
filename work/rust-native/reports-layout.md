# Rust 2.0.0-beta.2 布局恢复与验证报告

本版以正式版 v1.0.17 的界面和操作为参照，在 Rust 原生界面中恢复布局。运行时仍使用 eframe/egui + OpenGL，不启动浏览器引擎。本报告对应最终可执行文件 SHA-256：`1fde1b25f494b24e3f2891b64f737e60695c78796686337d64a026960bcecee0`。

## 恢复范围

- 恢复窄侧栏、原版图标与配色、辉月伊形象、顶部页签、集成窗口按钮、返回/前进和全局搜索。小窗口侧栏可滚动，世界档案入口保持可用。
- 配种查询恢复左侧物种列表、右侧紧凑组合卡片。默认窗口为 3 列 × 10 行，可完整看到 30 个组合及分页；支持 60、120 和全部。保留反查、属性筛选、刷新位置和图鉴关联。
- 仓库恢复按个体显示的图片、名称、性别、词条和分页；同种多只保持分开。子代恢复父母摘要和路线弹窗；目标配种恢复计划保存、加载、孵化记录及手术台词条。更改目标词条会立即清除旧路线并作废旧计算任务。
- 词条恢复按稀有程度排序及等级图片；在默认尺寸的词条窗口可同屏看到全部 115 项。
- 帕鲁、技能、物品、单位等详情使用分区卡片和具名表格，恢复各自筛选条件。伙伴技能可切换等级；物品可查看制作数量、配方路径、掉落来源和商人坐标；任务、手记、探索奖励、设施、远征和据点生产保留关联操作。
- 地图恢复侧栏分类筛选、官方图标、浮动点位详情、悬停等级、坐标定位和缩放按钮。保留完成标记、自定义点位、刷新位置、重叠点位选择及地图切换。
- 世界档案恢复弹窗形式及扫描、导入、备份操作。计算器分别保存输入，恢复属性、远征属性、工作效率、捕捉概率和遗物转换的分区布局。

保持原有资料：300 个帕鲁物种、2,466 个物品、12,942 个地图源点、5,110 个全局搜索条目。本次增量核验确认打包的游戏资料文件与 beta.1 完全相同。

## 功能验证

工作区回归检查共 64 项通过：57 项应用测试、1 项核心对照测试（涵盖 1,942 个对照用例），以及单独启用的 6 项公共存档测试。最终压紧配种卡片后再次运行的 6 项配种测试均通过；它们属于上述应用测试，不重复计数。

真实原生窗口中完成点击、键盘与截图检查，覆盖：

- 默认窗口和 960×620 小窗口的配种、子代、仓库、地图、世界档案与侧栏入口。
- 查询分页、显示全部 298 个棉悠悠组合、反查结果、名称到刷新地图的跳转；默认窗口完整显示 30 组。
- 115 项词条选择、现有帕鲁参与配种、已有目标仍计算新孵化路径、更改词条使旧路线失效。
- 伙伴技能等级与效果、帕鲁图鉴、物品配方数量、商人坐标、远征和相关详情页面。
- 属性/远征属性、捕捉概率的实际输入变化与结果变化。
- 地图拖动、分类、等级悬停、完成标记及撤销、坐标定位、世界档案打开与关闭。
- 全局搜索输入、回车进入详情、返回与 Esc 关闭；真实点击默认及小窗口的世界档案入口。

测试使用公共样本导出的 467 只帕鲁档案，在临时目录中运行；没有修改真实游戏存档。测试检查既有库存和记录的保留情况。自动检查和抽样界面操作不能证明所有电脑、所有存档或每一种点击顺序都无问题。

## 最终构建的延迟对比

比较 beta.1 与最终 beta.2，使用同一份 467 只帕鲁档案。每个版本预热 1 次并排除；随后交替运行 5 次，表内为各轮指标的中位数。样本文件 SHA-256：`5f7af3f4534da06920bac3eb28524b5db5adbcfd5980c953c0f377054f6c2e6c`。

| 测试条件与指标 | beta.1 | beta.2 | 变化 |
| --- | ---: | ---: | ---: |
| 默认 CPU：进程创建至首页第二次 UI 绘制 | 365.88 ms | 372.26 ms | +6.38 ms |
| 默认 CPU：启动截图回调 | 547.63 ms | 553.21 ms | +5.59 ms |
| 默认 CPU：地图首次可用 | 57.55 ms | 63.47 ms | +5.93 ms |
| 默认 CPU：拖动单帧 CPU 中位数 | 0.930 ms | 1.510 ms | +0.580 ms |
| 默认 CPU：拖动单帧 CPU P95 | 1.543 ms | 2.072 ms | +0.530 ms |
| 限制 2 个逻辑核心：首页第二次 UI 绘制 | 352.91 ms | 380.36 ms | +27.45 ms |
| 限制 2 个逻辑核心：启动截图回调 | 358.48 ms | 387.64 ms | +29.16 ms |
| 限制 2 个逻辑核心：地图首次可用 | 53.97 ms | 64.37 ms | +10.40 ms |
| 限制 2 个逻辑核心：拖动单帧 CPU 中位数 | 1.093 ms | 1.184 ms | +0.091 ms |
| 限制 2 个逻辑核心：拖动单帧 CPU P95 | 1.647 ms | 1.469 ms | −0.178 ms |

恢复完整界面后，本轮启动和地图平均处理开销略有增加，不能称为性能提升。5 次样本有系统调度波动，不足以把全部差异归因于代码。本轮主要检查功能恢复后的延迟水平。

计时范围：启动 UI 指标来自进程创建时间到原生界面第二次绘制；截图回调是 GPU 图像回传时刻，包含等待，不能当作屏幕发光延迟。两个版本均在首页闲置 5 秒后打开地图，以 4 倍缩放连续拖动 90 帧。拖动指标是 CPU 处理时间，不是端到端输入延迟或完整 GPU 帧时间。默认条件开放 32 个逻辑核心；2 核测试仅限制被测进程，不代表旧硬盘、旧显卡或真实低配电脑。样本均为热启动，未清空操作系统文件缓存。

原始汇总保存在同目录的 `reports-layout-performance-all.json` 和 `reports-layout-performance-cpu2.json`，含所有样本与两个可执行文件的校验值。
