# Rust beta.11 · 窗口大小调整修复

无边框窗口缺少原生边缘命中处理：窗口允许缩放，但四边和四角均被识别为普通客户区，无法用鼠标开始缩放。左侧栏的固定宽度与这个问题无关，圆角裁剪也保留了四边中点。

本版通过 Windows 窗口子类回调补上四边和四角的原生缩放方向；边缘命中宽度为7个逻辑像素，角部沿边延伸20个逻辑像素，按窗口DPI换算。窗口明确启用缩放。最大化、最小化和不可缩放状态交回原有处理；其余消息继续走原窗口过程，保留最小尺寸、标题栏拖动、三个窗口按钮、系统光标及原生缩放循环。销毁时移除回调，不持有应用数据指针。

实现使用系统自带的 [SetWindowSubclass](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass) 和 [DefSubclassProc](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-defsubclassproc)，未新增第三方运行环境。

## 修复前后验证

使用同一份公开467只帕鲁测试档案和隔离测试窗口，未读取真实游戏存档。旧版beta.10四边四角全部返回普通客户区，无法从边缘启动缩放；系统菜单的调整大小命令仍能改变宽度，确认问题在边缘命中。

修复版四边、四角在正常、负屏幕坐标及还原后均返回正确方向，内容中心、标题栏和三个窗口按钮中心仍属于客户区。由右边缘命中启动 Windows 原生缩放循环后，使用方向键移动边界，窗口实际从2160×1350调整为2288×1350。第二次系统缩放调整至2422×1350；圆角区域随尺寸更新，没有保留旧宽度裁剪。

实际窗口测试在144 DPI（150%）进行，最小尺寸为1440×930物理像素，对应960×620逻辑像素。最大化时可见区域不触发边缘缩放，还原后恢复圆角和八方向命中。负坐标通过移动测试窗口验证，不代表已使用多台物理显示器逐台测试。

136项应用测试和1项核心回归集合通过，核心集合包含1942个案例。新增几何测试覆盖96、120、144、192、288 DPI下的方向和按钮命中，以及负屏幕坐标的有符号解包。需要外部存档研究语料的可选测试未重跑，存档解析没有修改。

全部窗口检查前后，467条仓库记录和地图标注哈希保持一致。安装包2125个文件、增量复原及立即更新、下次启动更新、失败恢复、多窗口保护均检查通过。游戏资料和图片资源不变；具体二进制和安装包哈希见同名JSON。安装向导未执行，解包和独立测试窗口检查未改动安装注册及快捷方式。
